2. ИДЕЯ
================================================================================

Многие приложения для бега построены вокруг GPS, расстояния, онлайн-карт,
облачной синхронизации и большого количества спортивных показателей.

Beakstorm Run использует другой подход.

Пользователь самостоятельно создаёт понятную визуальную последовательность
движения для конкретного пространства: стадиона, двора, парка, спортивного
зала, помещения или заранее известного маршрута.

Вместо необходимости постоянно смотреть на карту пользователь собирает
последовательность этапов.

Например:

Старт
↓
Лёгкий бег
↓
Контрольная точка
↓
Быстрый бег
↓
Изменение темпа
↓
Восстановление
↓
Финиш

Главная особенность приложения заключается в визуальном конструировании
тренировки.

Курица используется как тематический маркер старта.

Яйцо используется как тематическая контрольная точка.

Монета используется как тематический маркер изменения темпа или действия.

Перо используется как маркер восстановления.

Эти объекты являются исключительно частью визуального языка приложения.

Они не дают очков, наград, валюты, бонусов и не используются как игровые
механики.

После создания маршрута пользователь запускает тренировку.

Приложение последовательно показывает текущий этап, его продолжительность
и следующий этап.

Все основные функции работают полностью офлайн.

5. ОСНОВНОЕ РАБОЧЕЕ ПРОСТРАНСТВО
================================================================================

Главным рабочим пространством приложения является визуальный конструктор
маршрута.

Пользователь видит последовательность соединённых этапов.

На маршруте могут располагаться:

• стартовая точка с маркером курицы;

• этап лёгкой активности;

• этап обычного бега;

• этап быстрого бега;

• этап восстановления;

• этап остановки;

• контрольные точки с маркерами яйца;

• точки изменения темпа с маркерами монеты;

• точки восстановления с маркерами пера;

• прямые участки;

• повороты;

• развороты;

• круговые участки;

• финишная точка.

Каждый объект маршрута представляет функциональный этап или визуальный
маркер.

6. ОСНОВНОЙ ПРОЦЕСС ИСПОЛЬЗОВАНИЯ
================================================================================

1. Пользователь открывает приложение.

2. Выбирает готовый локальный шаблон или создаёт новую тренировку.

3. Добавляет этапы в нужной последовательности.

4. Настраивает продолжительность каждого этапа.

5. Выбирает тип активности.

6. При необходимости добавляет тематические визуальные маркеры.

7. Проверяет итоговую последовательность.

8. Запускает тренировку.

9. Выполняет текущий этап.

10. Приложение автоматически переключает пользователя на следующий этап.

11. После завершения результат сохраняется локально.

12. Пользователь может повторить тренировку или отредактировать её.

7. ОСНОВНЫЕ МЕХАНИКИ ПРИЛОЖЕНИЯ
================================================================================

ВИЗУАЛЬНЫЙ КОНСТРУКТОР МАРШРУТА

Главная функциональная механика приложения построена вокруг создания
последовательности тренировочных этапов.

Пользователь добавляет блоки движения и располагает их в нужном порядке.

Каждый блок описывает конкретное действие.

Например:

• лёгкий бег;

• обычный бег;

• быстрый бег;

• восстановление;

• остановка.

Последовательность отображается как единый визуальный маршрут.

-------------------------------------------------------------------------------

НАСТРОЙКА ЭТАПОВ

Каждый этап может иметь собственную продолжительность.

Пользователь может изменять:

• тип активности;

• длительность;

• порядок;

• положение в последовательности;

• визуальный маркер.

Это позволяет создавать короткие и длинные тренировки под конкретное
пространство и индивидуальный сценарий.

-------------------------------------------------------------------------------

TEMPO SECTIONS

Приложение поддерживает несколько базовых режимов активности:

Walk

Easy Run

Run

Fast Run

Recovery

Stop

Каждый режим имеет собственное визуальное обозначение.

Это позволяет быстро понимать структуру тренировки без чтения большого
количества текста.

-------------------------------------------------------------------------------

CHICKEN START MARKER

Курица обозначает начало созданного маршрута.

Она используется как тематический визуальный элемент.

Маркер не является персонажем.

Пользователь не управляет курицей.

Курица не участвует в игровом процессе.

-------------------------------------------------------------------------------

EGG CHECKPOINT MARKER

Яйцо обозначает контрольную точку.

Оно может использоваться для визуального разделения длинной тренировки на
понятные части.

Например:

• окончание первого интервала;

• начало восстановления;

• переход к следующему кругу;

• контрольная точка маршрута.

-------------------------------------------------------------------------------

COIN TEMPO MARKER

Монета используется как тематический визуальный маркер изменения темпа.

Она может обозначать:

• ускорение;

• переход к новому режиму;

• начало интенсивного участка.

Монета не является игровой валютой.

Она не собирается и не используется для покупки каких-либо улучшений.

-------------------------------------------------------------------------------

FEATHER RECOVERY MARKER

Перо используется как визуальный символ восстановления.

Оно помогает быстро выделить на маршруте:

• отдых;

• снижение темпа;

• восстановительный интервал.

-------------------------------------------------------------------------------

ROUTE PREVIEW

Перед запуском пользователь видит всю тренировку как единую визуальную
последовательность.

Это позволяет проверить:

• порядок этапов;

• длительность;

• смену темпа;

• расположение контрольных точек;

• общую структуру тренировки.

-------------------------------------------------------------------------------

OFFLINE RUN MODE

Во время тренировки интерфейс становится максимально простым.

На экране отображаются:

• текущий тип активности;

• большой таймер;

• визуальный маркер текущего этапа;

• следующий этап;

• кнопка паузы.

Пользователю не требуется постоянно возвращаться в конструктор маршрута.

-------------------------------------------------------------------------------

AUTOMATIC STAGE TRANSITION

После завершения заданного времени приложение автоматически переходит к
следующему этапу.

Переход сопровождается коротким звуковым сигналом.

Это позволяет выполнять тренировку с минимальным взаимодействием с экраном.

-------------------------------------------------------------------------------

LOCAL HISTORY

После завершения тренировки приложение локально сохраняет:

• название тренировки;

• дату;

• продолжительность;

• количество этапов;

• использованный шаблон.

Информация хранится на устройстве.

-------------------------------------------------------------------------------

LOCAL STATISTICS

Приложение рассчитывает простую локальную статистику:

• общее количество тренировок;

• общую продолжительность;

• среднюю продолжительность;

• распределение типов тренировок;

• активность по периодам.

Для основной функциональности не требуется передача данных на сервер.

9. ОГРАНИЧЕНИЯ И ВАЛИДАЦИЯ
================================================================================

Приложение контролирует корректность созданной последовательности.

Тренировка не должна запускаться без:

• хотя бы одного основного этапа;

• корректной продолжительности;

• определённой последовательности.

При создании маршрута пользователь получает понятное локальное сообщение,
если:

• продолжительность этапа равна нулю;

• маршрут не содержит активных этапов;

• присутствует некорректная последовательность;

• обязательный стартовый этап отсутствует.

Это не является системой поражения.

Пользователь может исправить тренировку и продолжить работу.

14. БАЛАНС ФУНКЦИОНАЛЬНОСТИ И НАГРУЗКИ
================================================================================

Поскольку Beakstorm Run является приложением, а не игрой, игровой баланс,
сложность уровней и система наград отсутствуют.

Вместо этого используется баланс функциональной нагрузки и сложности
создания тренировок.

-------------------------------------------------------------------------------

НАЧАЛЬНОЕ ИСПОЛЬЗОВАНИЕ

Пользователь работает с:

• 3–4 базовыми типами этапов;

• короткими тренировками;

• готовыми шаблонами;

• простой последовательностью действий.

Рекомендуемая длительность:

5–15 минут.

Основная задача — быстро создать и запустить тренировку без сложной
настройки.

-------------------------------------------------------------------------------

СРЕДНЕЕ ИСПОЛЬЗОВАНИЕ

Пользователь начинает:

• комбинировать типы активности;

• использовать контрольные точки;

• чередовать темп и восстановление;

• создавать собственные последовательности.

Рекомендуемая длительность:

15–40 минут.

Оптимальное количество этапов:

5–12.

-------------------------------------------------------------------------------

РАСШИРЕННОЕ ИСПОЛЬЗОВАНИЕ

Пользователь может создавать более сложные последовательности.

Рекомендуемая длительность:

40–90 минут.

Оптимальное количество этапов:

12–24.

Для сохранения простого UX рекомендуется не перегружать один маршрут
слишком большим количеством мелких этапов.

-------------------------------------------------------------------------------

ОСНОВНОЙ ПРИНЦИП БАЛАНСА

Каждая тренировка должна оставаться:

• понятной;

• быстро создаваемой;

• визуально читаемой;

• удобной во время выполнения.

Увеличение количества этапов не должно автоматически делать интерфейс
сложнее.

Основной экран активной тренировки всегда показывает только текущий и
следующий этап.

• настройки интерфейса.

16. ЗВУК

Музыкальное сопровождение

Постоянное музыкальное сопровождение не является обязательным.

Основной акцент делается на короткие функциональные звуковые сигналы.

ЗВУКОВЫЕ ЭФФЕКТЫ

Интерфейс

• нажатие кнопки;

• открытие меню;

• закрытие меню;

• успешное сохранение;

• ошибка действия.

Конструктор

• добавление этапа;

• удаление этапа;

Тренировка

игрового интерфейса.

================================================================================
17. УСЛОВИЯ УСПЕШНОГО ЗАВЕРШЕНИЯ
================================================================================

Тренировка считается успешно завершённой, если пользователь:

• проходит все запланированные этапы;

или

• вручную завершает тренировку после выполнения необходимой части
  последовательности.

После завершения приложение:

• показывает краткий итог;

• сохраняет данные локально;

• добавляет запись в историю;

• обновляет локальную статистику.

================================================================================
18. НЕЗАВЕРШЁННАЯ ТРЕНИРОВКА
================================================================================

Тренировка может быть остановлена до завершения.

В этом случае пользователь может:

• завершить текущую сессию;

• не сохранять результат;

• сохранить информацию как незавершённую сессию, если такая функция
  предусмотрена в будущей версии.

Это не является поражением.

Отсутствуют:

• игровые попытки;

• штрафы;

• потеря валюты;

• снижение прогрессии;

• система проигрыша.

19. ИТОГ
================================================================================

Beakstorm Run («Клювовой Забег») — мобильное офлайн-приложение в категориях
Health & Fitness, Productivity, Utility и Offline Tools, построенное вокруг
визуального создания последовательностей для беговых и двигательных
тренировок.

Вместо GPS, онлайн-карт и постоянного подключения к интернету пользователь
создаёт понятную локальную схему:

создание маршрута
→
настройка этапов
→
предварительный просмотр
→
выполнение тренировки
→
локальное сохранение результата.

Курица, яйцо, монета и перо используются как единая тематическая система
визуальных маркеров.

Они не являются персонажами, игровой валютой, наградами или элементами
геймплея.

Приложение полностью работает без обязательного подключения к интернету,
не требует регистрации и хранит основные данные локально на устройстве.

Сочетание простого конструктора маршрутов, автоматического переключения
этапов, минималистичного режима тренировки, локальной истории и понятной
визуальной системы делает Beakstorm Run самостоятельным функциональным
мобильным приложением с возможностью дальнейшего расширения без изменения
основной офлайн-концепции.
